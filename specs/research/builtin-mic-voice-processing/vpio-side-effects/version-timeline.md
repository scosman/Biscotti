# VPIO-related changes by macOS version

Method: I fetched Apple's macOS 14, 15, 26 and 27 major-release notes through the docs JSON
endpoint (`developer.apple.com/tutorials/data/documentation/macos-release-notes/macos-NN-release-notes.json`)
and searched them for audio and voice-processing items. I also checked the WWDC sessions, SDK
headers and dated third-party reports cited below. Point-release (x.y) notes were not checked
one by one.

| macOS | What changed for VPIO / mic processing | Source |
|---|---|---|
| 10.12 Sierra (2016) | macOS ships a native echo canceller (Chrome's 2018 experiment used it) | [Chrome blog, 2018](https://developer.chrome.com/blog/macos-native-echo-cancellation/) |
| 10.15 Catalina (2019) | AVAudioEngine voice-processing mode (`setVoiceProcessingEnabled`, `voiceProcessingBypassed`, `…AGCEnabled`, `…InputMuted`). Ducking applied on VPIO creation *and* initialization | [WWDC19 510](https://developer.apple.com/videos/play/wwdc2019/510/); `AVAudioIONode.h` availability `macos(10.15)`; [cubeb comment](https://github.com/mozilla/cubeb-coreaudio-rs/blob/trailblazer/src/backend/mod.rs) |
| 10.13–11 | VPIO adds a reference "tap" input stream to speaker devices and "raw mic streams" on the built-in mic. Apple calls these "implementation details of AUVP" | [SO 64966350](https://stackoverflow.com/questions/64966350/voiceprocessingio-audio-unit-adds-an-unexpected-input-stream-to-built-in-output) (tested 10.13 → 11.0) |
| 12 Monterey (2021) | Mic Modes (Standard / Voice Isolation / Wide Spectrum) arrive, only for apps that adopt AUVoiceIO, on 2018+ Macs. `AVCaptureDevice.MicrophoneMode`, `preferred/activeMicrophoneMode`, `showSystemUserInterface(.microphoneModes)`. Firefox disables VPIO on 12 because "Using the VoiceProcessingIO audio unit on MacOS 12 causes crashes in OS code" | [Apple SE quoting WWDC21](https://apple.stackexchange.com/questions/430463/how-can-i-use-macos-montereys-new-mic-mode-feature-with-zoom), [Apple docs](https://developer.apple.com/documentation/avfoundation/avcapturedevice/microphonemode), [Firefox commit](https://github.com/mozilla-firefox/firefox/commit/8f5d908198964430a215bc48bcd0dbc07a46ae5c) |
| 13 Ventura (2022) | A Reddit thread is titled "Ventura finally added universal voice isolation". I could not read it, so this is unverified | [linked from Mozilla Connect](https://connect.mozilla.org/t5/ideas/voice-isolation-on-macos/idi-p/58586) |
| **14 Sonoma (2023)** | **Ducking API**: `kAUVoiceIOProperty_OtherAudioDuckingConfiguration` / `voiceProcessingOtherAudioDuckingConfiguration` (advanced ducking + Default/Min/Mid/Max). **Muted-talker detection** on macOS. **HAL VAD** (`kAudioDevicePropertyVoiceActivityDetectionEnable/State`) and HAL process input mute. **Voice Isolation for non-VPIO audio apps** ("From MacOS Sonoma 14.0 … for audio inputs that can be activated on audio applications"); the mic-mode UI moves to the Video/Audio menu-bar item. Ducking is now applied on VPIO *creation*. First VPIO unit per process takes > 3 s. "HAL Voice Isolation support" appears in logs (by Oct 2023) | [WWDC23 10235](https://developer.apple.com/videos/play/wwdc2023/10235/), SDK headers, [PreSonus](https://support.presonus.com/hc/en-us/articles/28066868202637-Audio-Interfaces-macOS-Sonoma-and-Sequoia-audio-quality-and-input-issues), [Apple 105117](https://support.apple.com/en-mz/105117), [cubeb mod.rs](https://github.com/mozilla/cubeb-coreaudio-rs/blob/trailblazer/src/backend/mod.rs), [Eclectic Light](https://eclecticlight.co/2023/10/21/what-happens-when-you-run-a-macos-vm-on-apple-silicon/) |
| 14.x on M2/M3 (2024) | Raw-array switch documented: the built-in mic exposes 3 very quiet channels to all apps while any app runs VPIO. Filed as FB13697689. VPIO instantiation 2–5 s (FB13879429) | [cubeb 361d2bb](https://github.com/mozilla/cubeb-coreaudio-rs/commit/361d2bbe65b464fee918dd2d4871205c071e3038), [Mozilla 1896938](https://bugzilla.mozilla.org/show_bug.cgi?id=1896938), [forum 756760](https://developer.apple.com/forums/thread/756760) |
| 15 Sequoia (2024) | **No VPIO items in the 15.0 release notes.** Everything above persists. Mismatched-device `-10875` reports (Jan 2025). The raw-array attenuation is reproduced on M4 / 15.3–15.5. Issue #66's Audient report is on 15 | release notes JSON; [forum 772006](https://developer.apple.com/forums/thread/772006); [Mozilla c53/c55](https://bugzilla.mozilla.org/show_bug.cgi?id=1896938) |
| 26 Tahoe (2025) | **No VPIO items in the 26.0 release notes** (only "Fixed: You might experience audio issues when using the Music app and changing the underlying audio device sample rate. (152465491)"). WWDC25 audio additions are capture-side and mostly iOS: `AVInputPickerInteraction`, AirPods high-quality recording, `AUAudioMix` / Cinematic Audio Mix (speech/ambience separation for Spatial Audio FOA recordings). The Mic Mode menu can now say "This app doesn't support" a mode. Raw-array attenuation reproduced on M5 / 26.5.1 and M3 Pro / 26.6.1. An issue-#66 user says Teams broke "since upgrade to MacOs 26.7" (cause unconfirmed) | release notes JSON; [WWDC25 251](https://developer.apple.com/videos/play/wwdc2025/251/); [Notey 2026](https://noteymeet.com/guides/mac-mic-modes-voice-isolation); [Mozilla c60, c63](https://bugzilla.mozilla.org/show_bug.cgi?id=1896938); [#66](https://github.com/scosman/Biscotti/issues/66) |
| 27 (2026) | **No VPIO items in the 27.0 release notes** apart from an AVFAudio fix: "Fixed: AudioDSP might crash when audio device properties change. (163978549)". AudioDSP is the framework that contains `AUVoiceProcessor` per [SO 67260345](https://stackoverflow.com/questions/67260345/mac-audiounit-audiocomponentinstancedispose-crash). No WWDC26 session on Core Audio or voice processing was found ([forum 829751](https://developer.apple.com/forums/thread/829751)). In the WWDC26 Audio Q&A an Apple engineer restated that VPIO ducking is intentional ([forum 829753](https://developer.apple.com/forums/thread/829753)). Hollow Chrome mic reported on 27.0.1 ([#66](https://github.com/scosman/Biscotti/issues/66)). WebKit 255986 still reproducible on 27.0.1 | release notes JSON; cited threads; [WebKit 255986](https://bugs.webkit.org/show_bug.cgi?id=255986) |

**Net:** the mechanisms that cause #66 (raw-array switch, ducking, aggregate and tap streams)
have not changed from macOS 14 through 27. The only cross-app knob Apple has added is the
macOS 14 ducking configuration. No version has a public way to keep VPIO from changing what
other apps get from the built-in mic.
